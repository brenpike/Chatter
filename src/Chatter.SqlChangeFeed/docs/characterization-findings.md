# Chatter.SqlChangeFeed — Characterization Findings

This document is a pure observation log produced during behavior-pinning (characterization) testing of `Chatter.SqlChangeFeed`. Every row records **current behavior as-is** as of this characterization pass — not desired or corrected behavior. The only change made to the production tree is a no-behavior `Properties/AssemblyInfo.cs` (`InternalsVisibleTo`, granting the test assembly access to internal types); no logic was altered and no version was bumped. Tests that pin these behaviors live under `src/Chatter.SqlChangeFeed/tests/`. SQL-string assertions are substring-based (whitespace-insensitive) by design, so emitted-script pins survive incidental reformatting. Each finding is flagged here for human review and prioritization; no code fix is prescribed.

| # | Unit | Pinned behavior | Why suspicious | Pinning test | Suggested follow-up |
|---|------|-----------------|----------------|--------------|---------------------|
| 1 | `SqlChangeFeedOptionsBuilder.Build()` | The `InvalidOperationException` message interpolates the runtime *value* of `_databaseName` (null/empty at throw time) instead of `nameof(_databaseName)`; the message reads `...via _connectionString or ` — `_connectionString` IS `nameof`, but the second token is the empty/null field value | Asymmetric diagnostics: one token is a field name, the other collapses to nothing, so the error tells the operator to fix a blank-named setting | `Configuration/UsingSqlChangeFeedOptionsBuilder/WhenConfiguring.cs` | Wrap the second token in `nameof(...)` so the message names `_databaseName` symmetrically |
| 2 | `SqlChangeFeedOptionsBuilder.WithReceiverTimeoutInMilliseconds` | The configured timeout flows to `ServiceBrokerOptions.ReceiverTimeoutInMilliseconds`, NOT `ReceiverOptions` | Grouping surprise: a "receiver timeout" lands on the service-broker options bag rather than the receiver options bag; pinned at the actual sink | `Configuration/UsingSqlChangeFeedOptionsBuilder/WhenConfiguring.cs` | Confirm the intended sink; if `ReceiverOptions` was meant, move the assignment |
| 3 | `SqlChangeFeedOptionsBuilder.WithChangeFeedDeadLetterServiceName` | Populates `ReceiverOptions.DeadLetterQueuePath`, while the public `SqlChangeFeedOptions.ChangeFeedDeadLetterServiceName` property is NEVER assigned on the `Build()` path — that public property is permanently `null` after `Build()` | Candidate latent bug: a public, documented property is dead after construction; callers reading it get `null` regardless of configuration | `Configuration/UsingSqlChangeFeedOptionsBuilder/WhenConfiguring.cs` | Assign the public `ChangeFeedDeadLetterServiceName` property during `Build()`, or remove it if `ReceiverOptions.DeadLetterQueuePath` is the real sink |
| 4 | `ChangeTypes` enum | `Insert == 1<<1` (== 2), not 1; no flag carries the value 1, so a cast/deserialized `1` maps to no member | A serialized or cast `1` silently resolves to "no matching flag"; the gap at value 1 is non-obvious for a `[Flags]`-style enum | `UsingChangeTypes/WhenCombiningFlags.cs` | Document the intentional gap or renumber so the first flag is `1` |
| 5 | `CreateChangeFeedTrigger` | `ChangeTypes.None` falls through to an `INSERT`-containing `AFTER` clause (silent default), so "watch nothing" silently emits a trigger that watches inserts | A caller asking to watch no change types gets an insert-watching trigger instead of an error or a no-op | `Scripts/Triggers/UsingCreateChangeFeedTrigger/WhenEmitting.cs` | Reject `None` explicitly, or emit no trigger when no change types are selected |
| 6 | `InstallAndConfigureSqlServiceBroker` / `UninstallSqlServiceBroker` | Null `deadLetterQueueName` / `deadLetterServiceName` are unguarded and emit empty-bracket names: `CREATE QUEUE dbo.[]` / `CREATE SERVICE []` / `DROP QUEUE dbo.[]` / `DROP SERVICE []` → malformed SQL | Null deadletter config silently produces invalid object names that would fail at execution time rather than at configuration time | `Scripts/ServiceBroker/UsingInstallAndConfigureSqlServiceBroker/WhenEmitting.cs`, `Scripts/ServiceBroker/UsingUninstallSqlServiceBroker/WhenEmitting.cs` | Guard against null, or skip the deadletter queue/service emission entirely when not configured |
| 7 | `CreateInstallationProcedure` | Asymmetric single-quote escaping inside one `EXEC` body: the nested service-broker script is doubled (`''`) while the nested trigger script is quadrupled (`''''`); `CreateUninstallProcedure` doubles BOTH (symmetric) | The two installation-procedure sub-scripts use different escaping depths in the same emitted body; divergence from the symmetric uninstall path invites copy/paste-style nesting bugs | `Scripts/StoredProcedures/UsingCreateInstallationProcedure/WhenEmitting.cs` | Confirm the nesting depth justifies the asymmetry; align the two sub-scripts if the quadrupling is unintended |
| 8 | `CreateInstallationProcedure` | `triggerName` is the only string constructor parameter NOT whitespace-guarded; a null `triggerName` constructs fine and lands in the emitted `OBJECT_ID('dbo.', 'TR')` | Inconsistent defensive construction within the same type: every other string param is guarded, so a null trigger name slips through to malformed emitted SQL | `Scripts/StoredProcedures/UsingCreateInstallationProcedure/WhenEmitting.cs` | Add a whitespace guard for `triggerName` to match the sibling parameters |
| 9 | `InstallChangeFeedScript` / `UninstallChangeFeedScript` | The base `ExecutableSqlScript` constructor runs `options?.ConnectionString` first, so null `options` throws `ArgumentException` (not `NullReferenceException`) before the subclass's own `_options ?? throw new ArgumentNullException(nameof(options))` guard runs — that guard is effectively DEAD for the null-options case | The subclass guard can never fire for null options because the base constructor rejects them first; the dead guard misleads maintainers about which exception type callers receive | `Scripts/UsingInstallChangeFeedScript/WhenEmitting.cs`, `Scripts/UsingUninstallChangeFeedScript/WhenEmitting.cs` | Validate `options` before the base constructor call, or remove the dead subclass guard |
| 10 | `SqlDependencyManager.InstallSqlDependencies` / `UninstallSqlDependencies`; `ExecutableSqlScript.Execute` / `ExecuteAsync` | DEFERRED COVERAGE (documented, never executed — recorded as a coverage gap, NOT a defect): these open a live `SqlConnection`, which is out of scope for in-memory characterization. `SqlDependencyManager` construction IS pinned (ctor stores the supplied `SqlChangeFeedOptions` on `Options`; null options construct without throwing and leave `Options` null) | Not suspicious — recorded so the coverage boundary is explicit and the live-connection paths are not mistaken for untested-by-omission | `UsingSqlDependencyManager/WhenConstructing.cs` (construction only; install/uninstall intentionally not exercised) | If end-to-end coverage is later desired, exercise these paths behind an integration-test harness with a real or containerized SQL Server |
