# Chatter.SqlChangeFeed — Characterization Findings

This document is a pure observation log produced during behavior-pinning (characterization) testing of `Chatter.SqlChangeFeed`. Every row records **current behavior as-is** as of this characterization pass — not desired or corrected behavior. The only change made to the production tree is a no-behavior `Properties/AssemblyInfo.cs` (`InternalsVisibleTo`, granting the test assembly access to internal types); no logic was altered and no version was bumped. Tests that pin these behaviors live under `src/Chatter.SqlChangeFeed/tests/`. SQL-string assertions are substring-based (whitespace-insensitive) by design, so emitted-script pins survive incidental reformatting. Each finding is flagged here for human review and prioritization; no code fix is prescribed. Rows whose behavior has since changed are marked **RESOLVED** with the issue that closed them; for those rows the *Pinned behavior* cell records current behavior rather than the behavior observed during the original pass.

| 1 | `SqlChangeFeedOptionsBuilder.Build()` | The `InvalidOperationException` message interpolates the runtime *value* of `_databaseName` (null/empty at throw time) instead of `nameof(_databaseName)`; the message reads `...via _connectionString or ` — `_connectionString` IS `nameof`, but the second token is the empty/null field value | Asymmetric diagnostics: one token is a field name, the other collapses to nothing, so the error tells the operator to fix a blank-named setting | `Configuration/UsingSqlChangeFeedOptionsBuilder/WhenConfiguring.cs` | Wrap the second token in `nameof(...)` so the message names `_databaseName` symmetrically |
| 2 | `SqlChangeFeedOptionsBuilder.WithReceiverTimeoutInMilliseconds` | The configured timeout flows to `ServiceBrokerOptions.ReceiverTimeoutInMilliseconds`, NOT `ReceiverOptions` | Grouping surprise: a "receiver timeout" lands on the service-broker options bag rather than the receiver options bag; pinned at the actual sink | `Configuration/UsingSqlChangeFeedOptionsBuilder/WhenConfiguring.cs` | Confirm the intended sink; if `ReceiverOptions` was meant, move the assignment |
| 3 | `SqlChangeFeedOptionsBuilder.WithChangeFeedDeadLetterServiceName` | **RESOLVED (#352).** `Build()` now passes the configured name to the `SqlChangeFeedOptions` constructor, so the public `ChangeFeedDeadLetterServiceName` property is populated alongside `ReceiverOptions.DeadLetterQueuePath`. `ChangeFeedObjectNames` reads that property, so a configured dead-letter service name drives the installed topology | Was a candidate latent bug: a public, documented property was dead after construction, so the configured name reached neither the installed objects nor a caller reading it back | `Configuration/UsingSqlChangeFeedOptionsBuilder/WhenConfiguring.cs`, `UsingChangeFeedObjectNames/WhenDeriving.cs` | None — closed |
| 4 | `ChangeTypes` enum | `Insert == 1<<1` (== 2), not 1; no flag carries the value 1, so a cast/deserialized `1` maps to no member | A serialized or cast `1` silently resolves to "no matching flag"; the gap at value 1 is non-obvious for a `[Flags]`-style enum | `UsingChangeTypes/WhenCombiningFlags.cs` | Document the intentional gap or renumber so the first flag is `1` |
| 5 | `CreateChangeFeedTrigger` | `ChangeTypes.None` falls through to an `INSERT`-containing `AFTER` clause (silent default), so "watch nothing" silently emits a trigger that watches inserts | A caller asking to watch no change types gets an insert-watching trigger instead of an error or a no-op | `Scripts/Triggers/UsingCreateChangeFeedTrigger/WhenEmitting.cs` | Reject `None` explicitly, or emit no trigger when no change types are selected |
| 6 | `InstallAndConfigureSqlServiceBroker` / `UninstallSqlServiceBroker` | **RESOLVED (#349).** Empty-bracket names can no longer be emitted. `InstallAndConfigureSqlServiceBroker` rejects a null or whitespace `deadLetterQueueName` / `deadLetterServiceName` in its constructor with `ArgumentException`. `UninstallSqlServiceBroker` still *constructs* with null dead-letter names, but `ToString()` throws `ArgumentException` out of `SqlIdentifier.Escape` instead of emitting `DROP QUEUE dbo.[]` | Was: null deadletter config silently produced invalid object names that failed at execution time rather than at configuration time | `Scripts/ServiceBroker/UsingInstallAndConfigureSqlServiceBroker/WhenEmitting.cs`, `Scripts/ServiceBroker/UsingUninstallSqlServiceBroker/WhenEmitting.cs` | None — closed. The install path fails at construction and the uninstall path at emit; both halves are pinned |
| 7 | `CreateInstallationProcedure` | **RESOLVED (#349).** The asymmetry itself was correct and is preserved — the nested trigger script really does sit one single-quoted layer deeper than the nested service-broker script. What changed is that it is now *expressed* through `SqlIdentifier.QuoteLiteral(value, nestingDepth)` (depth 2 for the trigger script, depth 1 for the service-broker script) rather than ad-hoc `Replace` calls, with the depth rule recorded as an `INVARIANT` comment. `CreateUninstallProcedure` still quotes both sub-scripts at depth 1 | Was: two sub-scripts using different escaping depths in one emitted body, with nothing stating why | `Scripts/StoredProcedures/UsingCreateInstallationProcedure/WhenEmitting.cs` | None — closed. The quadrupling is intended; do not "align" the two sub-scripts |
| 8 | `CreateInstallationProcedure` | **RESOLVED (#349).** `triggerName` is now whitespace-guarded in the constructor like every sibling string parameter; a null or whitespace trigger name throws `ArgumentException` instead of reaching the emitted `OBJECT_ID` literal | Was: inconsistent defensive construction within the same type, letting a null trigger name slip through to malformed emitted SQL | `Scripts/StoredProcedures/UsingCreateInstallationProcedure/WhenEmitting.cs` | None — closed |
| 9 | `InstallChangeFeedScript` / `UninstallChangeFeedScript` | The base `ExecutableSqlScript` constructor runs `options?.ConnectionString` first, so null `options` throws `ArgumentException` (not `NullReferenceException`) before the subclass's own `_options ?? throw new ArgumentNullException(nameof(options))` guard runs — that guard is effectively DEAD for the null-options case | The subclass guard can never fire for null options because the base constructor rejects them first; the dead guard misleads maintainers about which exception type callers receive | `Scripts/UsingInstallChangeFeedScript/WhenEmitting.cs`, `Scripts/UsingUninstallChangeFeedScript/WhenEmitting.cs` | Validate `options` before the base constructor call, or remove the dead subclass guard |
| 10 | `SqlDependencyManager.InstallSqlDependencies` / `UninstallSqlDependencies`; `ExecutableSqlScript.Execute` / `ExecuteAsync` | DEFERRED COVERAGE (documented, never executed — recorded as a coverage gap, NOT a defect): these open a live `SqlConnection`, which is out of scope for in-memory characterization. `SqlDependencyManager` construction IS pinned (ctor stores the supplied `SqlChangeFeedOptions` on `Options`; null options construct without throwing and leave `Options` null) | Not suspicious — recorded so the coverage boundary is explicit and the live-connection paths are not mistaken for untested-by-omission | `UsingSqlDependencyManager/WhenConstructing.cs` (construction only; install/uninstall intentionally not exercised) | If end-to-end coverage is later desired, exercise these paths behind an integration-test harness with a real or containerized SQL Server |
