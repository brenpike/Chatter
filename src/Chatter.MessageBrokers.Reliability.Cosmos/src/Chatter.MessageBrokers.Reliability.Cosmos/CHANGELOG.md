# Changelog

All notable changes to this project will be documented in this file.

This project follows [Keep a Changelog](https://keepachangelog.com/en/1.0.0/) and [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- Per-command document-tier participation registry and multi-container model (#238, ADR-0008): document-tier reliability is now opt-in PER COMMAND TYPE via a positive allowlist. `WithCosmosDocumentReliability<TCommand>(database, container, lease, resolver, partitionKeyPath...)` adds one registration per participating command type to a singleton `DocumentReliabilityRegistry`; participation IS having a registration, so a command type without one bypasses the document tier entirely (no resolver call, no batch). Multiple single-partition containers are supported — many command types may map to one container, but exactly one registration exists per command type (a duplicate registration for the same command type throws). Container handles are DERIVED (never provisioned) from the app-registered `CosmosClient` singleton via `client.GetContainer(database, container)` by the new singleton `CosmosContainerFactory`, cached thread-safely per `(database, container)`; the application owns the `CosmosClient` lifecycle and the existence of the database/container/lease (a documented prerequisite — the provider registers no client). ADR-0007's single-aggregate/single-partition hard constraint is unaffected; the registry adds container selection, not cross-partition atomicity.
- Document-tier outbox enqueue (#219): `CosmosBrokeredMessageOutbox` realizes `IBrokeredMessageOutbox.SendToOutbox` by resolving the active doc-tier atomic-write handle from the reliability surface and contributing the Chatter-owned outbox document's `CreateItemStream` op to the framework-owned `TransactionalBatch` (it never executes the batch — the Document-Tier Batch-Lifecycle Behavior owns the single commit point). The outbox is container-agnostic — it stages onto whatever container the behavior opened the batch on, so it supports the multi-container registry above with no change. The outbox document (`CosmosOutboxDocument`) carries the `_chatterType="outbox"` discriminator, an `outbox:{encoded(MessageId)}` id via the shared Cosmos-id-safe encoder (`CosmosItemId`, reused by #220 for inbox markers), the raw `MessageId` verbatim, the `MessageContext` serialized with `ChatterJson.Options` (EF parity), the message body/destination/content-type, and `status="pending"`; the resolved partition-key value is stamped at the container's actual partition-key path (supporting a hierarchical path), not a fixed field. Registered as `IBrokeredMessageOutbox` with the outbox router in DI.
- Closed-by-construction staging contract on `ICosmosAtomicWriteHandle`: the framework-owned `TransactionalBatch` is no longer publicly reachable for op-adds. All staging goes through intent-revealing methods (`StageCreateItemStream`, `StageCreateItem<T>`, `StageUpsertItem<T>`, `StageReplaceItem<T>`, `StagePatchItem`), each of which calls the corresponding SDK batch op AND increments `StagedOperationCount` in one indivisible action. The ack-on-uncommitted class — stage an op via the raw batch without calling a count method → empty-batch guard reads 0 → skips `ExecuteAsync` → acks with nothing committed — is impossible by construction. `StagedOperationCount` is read-only for the behavior's empty-batch guard only; callers may not manipulate it independently. `StageCreateItemStream` is the Chatter-owned wire-shape path (outbox, #220 inbox marker); the typed `Stage*Item<T>` methods go through the SDK serializer (app aggregate writers, typed markers). The `CosmosBatchExecutionException.StatusCode` response-inspection seam is unchanged — #220 can still distinguish a confirmed-duplicate inbox-marker 409. Closes the first of the two deferred P1 skeleton findings.
- Batch-response inspection in the Document-Tier Batch-Lifecycle Behavior: after the single `ExecuteAsync`, a non-success `TransactionalBatchResponse` throws `CosmosBatchExecutionException` so the message is not acked when the writes did not commit (a forced aggregate ETag/412 surfaces here). The inspection is structured as a clean seam so #220 can later distinguish a confirmed-duplicate inbox-marker 409. The empty-batch guard (skip `ExecuteAsync` when no op was staged) is preserved. Closes the second deferred P1 skeleton finding.

### Changed

- The `ResolvePartitionKey` delegate is now Try/nullable (`PartitionKey?`): a `null` return means "no resolvable partition for this message", in which case the Document-Tier Batch-Lifecycle Behavior opens no batch and bare-passes-through to `next()`. The resolver is only ever invoked for registered participants, so the prior null-inbound NRE (an in-process command's `null` inbound message reaching an unguarded resolver) is eliminated by construction. `DocumentTierBatchLifecycleBehavior<TMessage>` is rewritten to be registry-gated: a registry miss is a bare pass-through; a registry hit resolves the partition key, derives the registration's container via `CosmosContainerFactory`, and opens the batch on it.
- The Cosmos DI registration no longer accepts eager `Container` instances. The eager two-`Container`-instance `WithCosmosDocumentReliability` overload is REMOVED in favor of deriving handles from the app-owned `CosmosClient`; a per-registration `Func<IServiceProvider, Container>` factory overload is kept for applications that resolve their containers from the service provider themselves. The single-container DI holders (`DocumentContainer` / `LeaseContainer`) are superseded by the registry + factory and removed.

### Fixed

- Non-participant dispatch no longer throws from the Cosmos outbox (#238, ADR-0008). `WithCosmosDocumentReliability<T>` globally replaces the outbound `IRouteBrokeredMessages`, but only PARTICIPANT command types open a document-tier batch (which sets the surface handle); previously a NON-registered command whose handler Send/Published routed straight into `CosmosBrokeredMessageOutbox`, which threw `InvalidOperationException` on the null handle — contradicting "a command type without a registration bypasses the document tier entirely". Routing is now gated by a closed-by-construction `HandleGatedOutboxRouter` decorator: when the surface handle is null (every non-participant dispatch, and every dispatch after a participant's batch scope closes) routing delegates to the core-registered DEFAULT infrastructure router, exactly as if Cosmos were not installed; only a participant's mid-batch dispatch (handle set) routes through the Cosmos outbox — unchanged. The decorator captures the core default descriptor BEFORE the replace (which removes it first), honoring its lifetime and all three descriptor shapes, and is idempotent across multiple `WithCosmosDocumentReliability<T>` calls (no double-wrap). The `CosmosBrokeredMessageOutbox` null-handle throw is retained as a hard wiring-error guard the decorator now ensures non-participants never reach.
- Multi-message outbox drain (#219): each outbox document in a `SendToOutbox` call with two or more messages now stamps its own freshly-derived partition-key node (minted per document from a detached `JsonElement`). Previously, shared `JsonNode` instances resolved once in `SendToOutbox` were re-stamped across documents; on the second message the already-parented node threw, the batch never executed, and the message redelivered forever. Cross-document node re-parenting is now structurally impossible — the `JsonElement` value type carries no parent reference, and each `ToJsonObject` call mints a fresh `JsonNode` at stamp time.

## [0.1.0] - 2026-06-14

### Added

- Initial document-tier (Cosmos DB) reliability provider **skeleton** (#218): the package and DI surface, the document-tier reliability surface (the doc-tier atomic-write handle — sibling of `IPersistanceTransaction` — carrying the bound container, the open `TransactionalBatch`, the resolved partition-key value, and the container's partition-key path), the app-registered partition-key resolver, and the Document-Tier Batch-Lifecycle Behavior **shell** registered as the outermost pipeline behavior. The behavior opens a `TransactionalBatch` on the resolved partition and executes it once after the handler — guarded so an empty batch (zero staged ops) never calls the Cosmos transport. The change-feed lease container is registered for the future relay. Outbox enqueue, inbox dedup marker, the change-feed relay, and the Cosmos emulator suite are **not** implemented in this release — they arrive in #219 (outbox), #220 (inbox), #222 (relay), and #223 (emulator suite).
