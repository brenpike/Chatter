STEP-008 of the rabbitmq-adapter initiative: Testcontainers RabbitMQ integration tests under `src/Chatter.MessageBrokers.RabbitMQ/tests/Integration/`. Structure mirrors the SSB integration suite exactly (own per-module `DockerEnvironment`/`RequiresDockerFactAttribute` — there is NO shared docker-gate in `tests/Chatter.Testing.Core`), `[Trait("Category","Integration")]` + `[RequiresDockerFact]`, `IAsyncLifetime` collection fixture, broker-agnostic `RecordingMessageHandler<T>`/`HandlerSignal`/`HandlerSignalRegistry` recorder.

**Why:** Prove the real Chatter pipeline (AddRabbitMq) round-trips/nacks/deadletters against a live broker; deadletter Max-Receives proven on BOTH Quorum and Classic per ADR-0001.

**How to apply (non-obvious gotchas):**
- **Testcontainers.RabbitMq 4.12.0** — pin to MATCH the repo's core Testcontainers 4.12.0 (the version SSB's Testcontainers.MsSql 4.12.0 pulls). Use the IMAGE ctor `new RabbitMqBuilder(image).Build()` NOT `new RabbitMqBuilder().WithImage(...)` — the parameterless ctor is `[Obsolete]` (CS0618), same reason SSB passes the image to `new MsSqlBuilder(image)`. Image `rabbitmq:3.13-management` (quorum native `x-delivery-count` needs >=3.8). `RabbitMqContainer.GetConnectionString()` returns an `amqp://` URI fed straight into `RabbitMqOptions.Uri`.
- **Topology is declared IN-TEST** (adapter provisions NOTHING). `RabbitMqTopology.DeclareAsync` opens a RabbitMQ.Client connection and `QueueDeclareAsync` the work queue with `x-queue-type` arg (`quorum`/`classic`) + a plain durable DLQ, plus an optional direct exchange + binding for the `WithRabbitMqRouting` case. Per-scenario `RabbitMqObjectSet` (queue-type-suffixed names) keeps Quorum/Classic variants on distinct queues.
- **Deadletter per-queue-type proof shape (maxReceiveAttempts: 1):** Quorum → first delivery attempts = native `x-delivery-count`(0)+1 = 1 >= 1 → deadletters IMMEDIATELY (no redelivery). Classic → first delivery attempts = `x-chatter-delivery-count`(absent=0) = 0, NOT >=1 → classic republish to work queue with header=1 (confirmed) → redelivery attempts=1 >=1 → deadletters. Two `[RequiresDockerFact]` delegating to one shared body; QueueType is the only difference.
- **DLQ read at the test edge** via raw `BasicGet(autoAck:true)`. The RabbitMQ body is the RAW command JSON (NOT an OutboundBrokeredMessage envelope like SSB). Failure metadata lives in the AMQP HEADERS (the republish merges inbound headers + `FailureDetails`/`FailureDescription` overrides). AMQP string headers arrive as `byte[]` — decode tolerantly. `MessageContext.ReceiveAttempts` is NOT on the wire (stamped on the inbound context at receive time), so do NOT assert it on the DLQ envelope; `InfrastructureType` IS (stamped on send via SendOptions, carried through).
- **Send routing:** harness stamps `MessageContext.InfrastructureType` in `SendOptions` so the dispatcher routes to the RabbitMQ sender. `WithRabbitMqRouting` is exercised by stamping `RabbitMqMessageContext.TargetExchange`/`RoutingKey` into SendOptions message-context (flows into the OutboundBrokeredMessage the sender's `ResolveAddress` reads) — destinationPath stays the queue name.
- **`dotnet restore --force-evaluate` side-effect (same as ASB-SDK-migration):** refreshing the test lock file ALSO rewrites 4 SIBLING lock files (CQRS, MessageBrokers, Reliability.EntityFramework, shared `tests/`). REVERT them (`git checkout -- <each>`) to stay in scope — only `src/Chatter.MessageBrokers.RabbitMQ/tests/packages.lock.json` is assigned.
- **Docker-gate env nuance:** a plain `dotnet test` in THIS WSL env FAILS (not skips) the 5 integration tests with `DockerUnavailableException` — the documented Docker-API-version-mismatch condition that hits SSB (5 fail) and ASB (~18 fail) IDENTICALLY. The gate is correct: with Docker genuinely unreachable (e.g. `DOCKER_HOST=tcp://127.0.0.1:1`) all 5 SKIP cleanly; with `--filter Category!=Integration` (the PR-CI path) only the 106 unit tests run. See [[rabbitmq-unit-test-suite]], [[project_asb-integration-tests]].
